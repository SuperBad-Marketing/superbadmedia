Section 01

What the Outreach System Does

The outreach system is a fully automated cold-email pipeline. Every day at 3am Melbourne time, it discovers local businesses through public APIs, enriches them with nine categories of signal data, scores each prospect against two track rulesets (retainer and SaaS), generates a unique LLM-drafted cold email for every qualified prospect, and queues those drafts for human approval.

There are no templates. No variable substitution. Every email is written end-to-end by Claude Opus for that specific prospect, referencing their actual advertising spend, their Google reviews, their website quality, their Instagram cadence — whatever the enrichment pipeline found. The email identifies a specific gap in their marketing and gives them a free win they can act on without SuperBad.

Andy approves drafts from a single queue. As he approves enough without edits, the system earns autonomy per track — eventually auto-sending with a 15-minute cancellation window. If anything goes wrong (spam complaint, hard bounce, voice drift), a circuit breaker fires and the system drops back to manual approval.

Two tracks share one pipeline:

  • Retainer track — higher-revenue, multi-stakeholder businesses that would benefit from SuperBad’s creative + performance retainer.
  • SaaS track — lean-team, DIY-leaning businesses that would benefit from SuperBad’s subscription products.

Every prospect gets scored against both tracks. Highest qualifying score wins. Below the floor on both? Discarded. No second chances.

Section 03

Discovery Sources

Three discovery sources run in parallel on every daily search. No Apollo.io, no purchased contact databases. Everything is built from publicly available APIs.

SourceWhat It FindsImplementation
Meta Ad Library Businesses actively running Facebook/Instagram ads. Filters: location, active-ad status, ad count, estimated spend bracket. sources/apify-meta-ad-library.ts — Apify actor runner
Instagram Location Businesses with local Instagram content presence — tagged posts, geo-anchored accounts. sources/apify-instagram-location.ts — Apify actor runner
Google Maps Location-based businesses not necessarily running ads. Query shape: category + location from search verticals. sources/google-maps.ts — SerpAPI google_maps engine

Broad Sweep Category Rotation

Google Maps searches auto-cycle through 12 categories on each run — restaurants, retail, health and beauty, professional services, fitness, trades, automotive, hospitality, creative, education, food and beverage, medical. This catches businesses that don’t run ads and wouldn’t appear in the Meta library. The category rotates automatically; no manual input required.

Search Verticals

The search_verticals table defines standing search parameters: name, category, location (lat/lng + radius), country code, standing brief, weight (priority), and active status. The daily search runner picks verticals by weighted rotation, favouring those searched least recently. Andy manages these from the admin verticals page.

Deduplication

After discovery, every candidate is checked against:

  1. lead_candidates.domain within a 90-day dedup window
  2. deals (any existing deal for the same company/domain)
  3. dnc_emails, dnc_domains, companies.do_not_contact via isBlockedFromOutreach()

Cross-source priority for duplicates: Meta Ads > Instagram > Maps. If Meta and Maps find the same business, the Meta entry wins because it carries richer advertising signals.

Enrichment Pipeline

Every discovered candidate flows through nine enrichment sources in parallel. Each source is optional — the pipeline degrades gracefully when any source fails, returns nothing, or times out. The combination builds a ViabilityProfile stored as JSON on the candidate row.

#SignalSourceWhat It Tells Us
1 Active ads + spend bracket Meta Ad Library API Marketing maturity + budget presence. High spend = retainer signal. Any spend = not DIY-only.
2 Google Ads activity Google Ads Transparency Center (SerpAPI) Cross-platform marketing maturity. Catches “runs Google ads but not Meta” segment.
3 Website technical quality Google PageSpeed Insights API Proxy for agency-vs-DIY website. Low score = needs help (SaaS signal). High score = existing investment (retainer signal).
4 Domain age whois lookup Business longevity. Newer businesses lean SaaS; established businesses lean retainer.
5 Instagram presence Instagram Business Discovery API Follower count, post count, recent post cadence. Social maturity + audience size.
6 YouTube presence YouTube Data API v3 Subscriber count, video count, upload cadence. Long-form content = strong retainer signal.
7 Google Maps reviews + rating SerpAPI Review count, average rating, business category. Consumer business legitimacy + size proxy.
8 Website scrape Custom fetch + cheerio About page, team page, pricing page. Team size signal, service list, stated pricing tier.
9 Maps photo count + recency SerpAPI Photo count + last photo date. Recency of business activity. Recent photos = actively managed.

Deep Enrichment (Post-Scoring)

After initial scoring, qualified candidates get a second enrichment pass via Apify actors: Facebook page data, LinkedIn company info, TikTok profile, and full website content crawl. This produces a distilled_brief — an LLM-summarised description of the business that feeds into the email generator’s prompt. Deep enrichment data lives inside the same ViabilityProfile under facebook, linkedin, tiktok, and website_content fields.

Section 05

ICP Scoring

The Scoring Engine

All scoring rules live in one file: lib/lead-gen/scoring.ts. Pure functions, no I/O, no side effects, fully unit-testable. Both track scorers decompose into four sub-scorers — advertising, web, social, and maps — each capped at a maximum contribution.

Scoring Interface
function scoreForSaasTrack(profile: ViabilityProfile, softAdjustment = 0): { score: number; breakdown: ScoringBreakdown; qualifies: boolean }
function scoreForRetainerTrack(profile: ViabilityProfile, softAdjustment = 0): { score: number; breakdown: ScoringBreakdown; qualifies: boolean }

Qualification Floors

ConstantValueMeaning
SAAS_FLOOR8Minimum score to qualify for the SaaS track. Below this the candidate is too thin to justify a cold touch.
RETAINER_FLOOR14Minimum score to qualify for the retainer track. Higher bar because retainer pitches are higher-stakes and higher-cost.

Floors are constants in scoring.ts. Changes ship as deploys, not config. There is no scoring rules UI.

How Scores Are Computed (SaaS Example)

Sub-ScorerMaxKey Rules
Advertising 20 Active Meta creatives +5, 3+ ads +3, medium spend +4. Active Google campaigns +4. High spend only +2 (too big for SaaS).
Web 30 Bad PageSpeed +5 (needs help), young domain +4, solo team +6, small team +4, budget pricing +3.
Social 25 Moderate Instagram (0–5k) +5, active posting +3, any YouTube +2.
Maps 25 5+ reviews +3, 20+ reviews +2 more, 4.0+ rating +3, 5+ photos +2, recent photos +2.

Retainer scoring inverts several signals: high PageSpeed is rewarded (existing web investment), large teams are preferred, premium pricing signals high LTV, big Instagram followings are valuable. The same enrichment data tells different stories depending on the track.

Winner-Takes-All Track Assignment

lib/lead-gen/scoring.ts
function assignTrack(profile): { track: 'saas' | 'retainer' | null; score: number } {
  const saas = scoreForSaasTrack(profile)
  const retainer = scoreForRetainerTrack(profile)

  if (!saas.qualifies && !retainer.qualifies) return { track: null, score: 0 }
  if (saas.qualifies && !retainer.qualifies) return { track: 'saas', score: saas.score }
  if (retainer.qualifies && !saas.qualifies) return { track: 'retainer', score: retainer.score }
  return saas.score >= retainer.score
    ? { track: 'saas', score: saas.score }
    : { track: 'retainer', score: retainer.score }
}

Reactive ICP Scoring (Post-Send)

Pre-send scoring is a snapshot. Once outreach begins, the prospect’s behaviour generates new signal. rescoreCandidate() adjusts scores based on engagement, replies, responsiveness, file notes, and bounces.

SignalAdjustmentCap
Click on any touch+5 per unique click+15
Full open (tier 2)+2 per event+6
No engagement (tier 4)−2 per event−8
Positive reply+12 (one-time)—
Objection / question reply+5—
Negative reply−15—
Replied within 24h+4—
No reply after 3+ touches−3—
File note exists on Deal+3—

Total reactive adjustment is bounded: [−20, +25] (constants REACTIVE_MIN and REACTIVE_MAX). Final score = clamp(base + adjustment, 0, 100). A rescore can change the qualified track, but only once per candidate — second flips are suppressed and logged.

Section 06

Email Generation

The Core Principle

No Templates

Every email is generated end-to-end per prospect by Claude Opus. No variable substitution, no fill-in-the-blank templates. Each email references specific signals from the prospect’s actual enrichment data. A/B testing happens at the strategy level, not the copy level.

Email Structure: Gap + Free Win + Soft CTA

  1. The Gap — a specific disconnect identified from enrichment data. Not flattery, not criticism. An observation that proves you actually looked. “Your Google reviews say one thing, your website says another.”
  2. The Free Win — actionable advice matched to signal complexity. Simple fix (under 30 min) = be prescriptive. Complex issue = be directional.
  3. The Soft CTA — proportional to zero prior relationship. “Worth a conversation if you’re curious.”

What the Prompt Sees

The system prompt composes these layers:

  • SuperBad’s own Brand DNA profile — outreach sounds like Andy, not a generic bot. Not the client’s Brand DNA (they’re not a client yet).
  • Brand voice examples — 5 real approved outreach emails loaded from the brand_voice_examples table (surface: “outreach”).
  • Viability profile — full structured JSON so the prompt can reference specific signals.
  • Deep enrichment brief — the website_content.distilled_brief (LLM-summarised description of the business).
  • Prior touches + engagement signals — for follow-ups, so the LLM never repeats an observation.
  • Funnel history — if the prospect previously started the trial shoot funnel and dropped off, the draft generator knows about it.
  • Standing brief — Andy’s strategic context for targeting.
  • Case snippet — if an approved anonymised proof point exists for the prospect’s vertical, it’s included.

Length Adapts to Touch Type

SituationGuidance
First touch3–4 sentences. Gap + free win + soft CTA.
Cold follow-up #23–4 sentences. Completely different signal. Must stand alone.
Proof touch #33–4 sentences. One sentence of proof from a similar business.
Breakup (touch 4+)2 sentences max. Acknowledge you’re done. No guilt.
Engaged follow-up (clicked)2–3 short paragraphs. They showed real interest — add substance.
Engaged follow-up (opened only)3–4 sentences. New angle, they read the last one.
Bonus touch (opened but never replied)2 sentences. Self-aware, dry.

Drift Check

Every generated draft passes through checkBrandVoiceDrift() using SuperBad’s own Brand DNA profile. On failure, one automatic regeneration with drift feedback. Second failure flags the draft with a visible amber warning in the queue — but does not block approval.

Subject Line Rules

  • Lowercase, conversational. Like a text from someone you know.
  • Vary style across touches: observation-lead, name-anchor, conversational, human.
  • Banned: fake “re:”, fake “fw:”, implied prior conversation, question hooks, exclamation marks, ALL CAPS, emoji.

If the subject needs a trick to get opened, the observation isn’t sharp enough. Fix the observation.

4-Touch Sequences

Cold Sequence Structure

TouchTimingContentSubject Style
1 Day 0 Gap + free win from primary enrichment signal Observation-lead: “87 reviews, 0 instagram posts”
2 Day 4 Different signal, different observation, completely standalone Name-anchor: “quick thought about [business]”
3 Day 11 One-sentence proof from similar business + connection Conversational: “something worth mentioning”
4 Day 21 Breakup — honest exit, no guilt Human: “last one from me”

Cadence Constants

Sequence Timing
Touch 1: sent on approval
Touch 2: 4 days after Touch 1
Touch 3: 7 days after Touch 2
Touch 4+: 10 days after prior touch

Engagement-Gated Continuation

The 4-tier engagement model determines whether a sequence continues:

TierConditionCutoff Counter Effect
1 — ClickAny link clickReset consecutive_non_engagements to 0
2 — Full OpenDwell ≥60s OR multiple opensReset to 0
3 — Sub-60s OpenSingle open, dwell <60s, no clicksIncrement by 1 (treated as non-engagement)
4 — NoneNo opens, no clicksIncrement by 1

After 3 consecutive non-engagements, the sequence transitions to stopped_engagement. Clicks always trump opens. Sub-60s opens are treated as noise because Apple Mail Privacy Protection prefetches typically dwell under 60 seconds.

After touch 4 with zero engagement: archive. Protect domain reputation. No sequence “ages out” — a highly engaged prospect could receive 20 touches over 8 months if they keep engaging.

Terminal States

stopped_engagement stopped_reply stopped_bounce stopped_unsubscribe stopped_manual

Reply Drop-Off Sequence

When a prospect replies and then goes quiet, a separate 3-step drop-off sequence activates:

Nudge 2Day 7Different approach. Proof or value reframe depending on their original question.

Section 08

Autonomy State Machine

The system earns the right to auto-send by demonstrating consistent draft quality. Autonomy is tracked per track — SaaS and retainer graduate independently.

State Diagram

MANUAL  — every draft needs explicit Approve click
    |  5 clean approvals
    v
PROBATION  — auto-send with 15-minute cancel window
    |  5 probation sends without intervention
    v
AUTO_SEND  — auto-send with 15-minute delay, maintenance enforced
    |  maintenance floor breached OR circuit breaker
    v
MANUAL  — streak resets to 0, must re-earn

Clean vs Non-Clean Approvals

Edit TypeClassificationStreak Effect
No editsCleanIncrements streak
Typo fix (≤3 chars, subject unchanged)MinorDoes not break streak
Phrasing tweak (body changed <20%, subject unchanged)MinorDoes not break streak
Subject line changedMaterialResets streak to 0
Body substantially rewritten (>20%)MaterialResets streak to 0
Nudge regenerationAlways materialResets streak to 0
Rejection—Resets streak to 0

Edit classification uses Levenshtein distance. The thresholds are configurable via settings: autonomy.minor_edit_char_threshold (default 3) and autonomy.material_edit_ratio_threshold (default 0.2).

Maintenance Standard

Once in auto_send, a rolling window of the last 20 sends is monitored. If the clean approval rate drops below 80%, the track demotes back to manual.

Circuit Breakers

Immediate demotion to manual with streak reset on any of:

  • Any hard bounce from an auto-send
  • Any spam complaint from any send
  • Any unsubscribe within 60 seconds of a send
  • Drift check flagged on any auto-send draft
Single Write Path

All autonomy state transitions route through one function: transitionAutonomyState(track, event) in lib/lead-gen/autonomy.ts. No direct writes to autonomy_state anywhere else. Every transition writes to activity_log. No silent flips.

Reply Classification

The Reply Intelligence Primitive

When a prospect replies, the system classifies the reply intent via a Haiku-tier LLM call and routes it to the appropriate handler. The classifier is a shared primitive — also consumed by the Hiring Pipeline and the Unified Inbox.

lib/reply-intelligence/classify.ts
function classifyReply({
  threadContext: { originalOutboundBody, recentMessages },
  replyBody: string,
  classificationContext: 'outreach' | 'hiring_invite' | ...,
}): Promise<{
  intent: 'positive' | 'objection' | 'question' | 'negative' | 'auto_responder',
  confidence: number,     // 0..1
  signals: string[],      // e.g. ['price_concern', 'timeline_pushback']
  summary: string,        // one-line human-readable
}>

Classification → Action Map

ClassificationLLM Draft?Andy Approves?Auto Action
Positive Yes — warm, match energy, answer what they asked. Include booking link when contextually relevant. Yes —
Question Yes — answer directly in 2–3 sentences, then soft CTA. Yes —
Objection Yes — acknowledge honestly, don’t argue. Leave door open. Yes —
Negative No No Auto-DNC, auto-archive, send “Done. Apologies for the interruption.”
Auto-responder No No Note return date on candidate. Re-queue touch for return date + 2 days.

Dispatch Table Pattern

Each consumer registers a handler map at module load. Dispatch lookup resolves (classificationContext, intent) → handler. Missing handler = structured error logged + fallback to queueForAndyReview.

lib/reply-intelligence/dispatch.ts
registerReplyDispatch('outreach', {
  positive: handlePositiveOutreachReply,
  objection: queueForAndyReview,
  question: queueForAndyReview,
  negative: suppressAndAutoArchive,
  auto_responder: ignoreAndRequeue,
})

Reply Draft Prompt Layers

  1. The original outreach email — subject, body, touch number, which gap/observation it used
  2. Their reply — full text, classified intent
  3. Viability profile + deep enrichment — full profile including the distilled business brief
  4. Standing brief — strategic context
  5. Brand voice + outreach voice examples — same anchors as outreach drafts
  6. Rules — match their energy, answer their actual question first, don’t repeat the original observation, don’t pitch

Andy can add a one-liner nudge that reshapes the reply draft: “mention ProTraxx”, “lead with the trial shoot.” The nudge overrides default behaviour.

Section 11

Kill Switches & Safety

Two Gate Functions

Every outbound send must pass through exactly two gate functions. No other code path adds candidates or sends email without calling both.

GateFileWhat It Checks
enforceWarmupCap() lib/lead-gen/warmup.ts Current warmup week, daily cap, sends today, scheduled touches. Returns { can_send, remaining }.
isBlockedFromOutreach() lib/lead-gen/dnc.ts Three-tier check: company → email → domain. First match wins. Returns { blocked, reason }.

Warmup Ramp

WeekDaily Cap
Week 15
Week 210
Week 315
Week 420
Week 5+30

Per calendar day in Melbourne timezone. Resets at midnight Melbourne. Non-overrideable — there is no “skip ahead” option. Week progression is computed from started_at, not manually advanced. The cap applies to all outbound cold outreach sends combined — first touches, follow-ups, stale nudges.

Do Not Contact (Three Tiers)

  1. Company-level: companies.do_not_contact flag on the company record.
  2. Email-level: dnc_emails table. Normalised (lowercase + trimmed). Unique constraint.
  3. Domain-level: dnc_domains table. Normalised. Unique constraint.

Population paths: unsubscribe link click, Resend spam complaint webhook (triple-writes: email + company + contact status), manual DNC management, CSV import.

Quiet Window

Automated outreach sends only during 08:00–18:00 Mon–Fri Melbourne time. Manual approvals are exempt (Andy is awake, he just clicked Approve). Rejected sends are deferred to the next safe window, not dropped.

Single Sender Identity

lib/lead-gen/sender.ts
export const SUPERBAD_SENDER = {
  display_name: 'Andy Robinson',
  local_part: 'hi',
  domain: 'contact.superbadmedia.com.au',
  reply_to: 'hi@contact.superbadmedia.com.au',
} as const

Cold outreach uses a dedicated subdomain (contact.superbadmedia.com.au) with its own SPF, DKIM, and DMARC records, fully isolated from the main domain. Every send imports this constant — no inline from-strings anywhere.

Unsubscribe Compliance

  • Every email includes a visible footer unsubscribe link + List-Unsubscribe + List-Unsubscribe-Post headers (RFC 8058 one-click).
  • Unsubscribe tokens are server-signed (lib/lead-gen/unsubscribe-token.ts). No unsigned URLs anywhere.
  • Tokens never expire (legal requirement).
  • Handler: validates token → inserts to dnc_emails (idempotent) → renders confirmation page.

Retargeting Pixels on Outreach Links

All outreach email links (except unsubscribe) are wrapped through a redirect endpoint that fires Meta Pixel and Google Ads conversion tags before redirecting to the target URL. HMAC-signed tokens prevent URL tampering. Pixel IDs are configured via settings; if unconfigured, the redirect silently skips. No cookies are set by the redirect page itself.

Spam Act Footer

Every outbound email includes: Andy Robinson · SuperBad Media · Melbourne, Australia, reason for sending (“Your business appeared in public advertising directories”), and the unsubscribe link. Non-negotiable. The system prompt instructs the LLM to always include this.

Section 12

Implementation Tips

  1. Build enrichment before scoring. The enrichment pipeline is the largest failure surface (nine APIs, each with its own rate limits and failure modes). Get each enrichment source working independently, verify graceful degradation when sources fail, then wire them into the viability profile. Scoring is trivially testable once you have profile fixtures.
  2. Scoring is pure functions — test it first. scoreForSaasTrack() and scoreForRetainerTrack() take a ViabilityProfile and return a number. No I/O, no database, no API calls. Write unit tests for every sub-scorer path before anything else. The scoring_debug_json field exists specifically so you can eyeball “why did this score 74.”
  3. Two gate functions are the whole safety model. enforceWarmupCap() and isBlockedFromOutreach() are the only two functions that protect compliance and domain reputation. Every new code path that touches outbound email must call both. If you bypass either, you have a regression.
  4. The autonomy state machine is the trickiest part. Four failure modes to test: graduates too early, graduates too late, circuit breaker fires silently, state machine bug. Manufacture test scenarios for all four. The metrics panel surfaces all states visibly — use it to verify.
  5. Prompts are the product. The draft generator’s system prompt is long and very specific. The quality of outreach emails is 90% prompt engineering. Invest in prompt iteration with real viability profiles. The voice examples table (brand_voice_examples where surface = 'outreach') is critical — without them the LLM will default to generic marketing copy.
  6. The engagement evaluator has a 24-hour cooloff. Sends are not classified until 24 hours after sending. This prevents Apple Mail Privacy Protection prefetches from triggering immediate tier classification. The evaluator runs periodically, picks up unclassified sends past the cooloff, and processes them in batch.
  7. Reactive scoring is additive, not replacement. The rescore function does not re-run enrichment. It takes the existing base score and applies bounded adjustments from engagement/reply/responsiveness signals. The adjustment is clamped to [−20, +25] — it can never push a zero-score candidate into qualification.
  8. Track changes are capped at one. A rescore can flip a candidate’s track (e.g. SaaS → Retainer) exactly once. The second flip is suppressed and logged. This prevents ping-pong between tracks on noisy engagement signals.
  9. Reply handling needs the full thread context. The reply draft prompt sees the original outreach email, the prospect’s reply, the viability profile, deep enrichment, and brand voice examples. Without thread context the LLM will produce generic replies that repeat the original observation. The “don’t repeat the observation” instruction is a hard rule.
  10. The 15-minute auto-send delay is enforced server-side. Not in the UI. Auto-send drafts are queued with a delay timestamp in the sequence runner. The cancel mechanism is a pure database operation that flips the draft status before the delay expires. No cron dependency for cancellation — the sequence runner checks status before firing.
  11. Case snippets auto-approve after 48 hours. If Andy doesn’t act on a pending case snippet within 48 hours, a scheduled task flips it to approved. This ensures the outreach pipeline always has fresh social proof without requiring Andy to manually curate it.
  12. Every mutation writes to activity_log. No Lead Gen code path writes to a Lead Gen table without an adjacent activity log row in the same transaction. This is non-negotiable. The activity log is how debugging and auditing work.
Final Note

This system sends real cold emails to real businesses. The warmup ramp, DNC enforcement, brand voice drift check, and quiet window gate are not features you can defer. They are the legal and reputational guardrails that make everything else safe to automate. Build them first, verify them thoroughly, and never route around them.
