Section 01

What Content Studio Does

Content Studio is a visual post creation tool for social media. You type a brief in plain English — “announce our new pricing” or “portfolio piece from the Thetford shoot” — and the system generates copy, renders it into branded typography images or animated videos, and uploads the output to Cloudinary. The result is publication-ready social content.

Content Engine is the autonomous pipeline that sits behind (and beside) the studio. It researches SEO keywords, generates full blog posts, rewrites them for newsletters, drafts social media versions per platform, tracks search rankings, and publishes — all voice-matched to the owner’s Brand DNA profile. It runs for SuperBad’s own content and as a SaaS product sold to subscribers.

Together they cover the full lifecycle: create → render → distribute → measure.

One brief in, published content out. The boring middle is the whole product.

The Two Systems at a Glance

SystemWhat It DoesWho Uses It
Content Studio Manual post creation — brief → copy → visual render → motion video Andy (admin), direct in the UI
Content Engine Autonomous SEO pipeline — keyword research → blog → newsletter → social → rankings SuperBad + SaaS subscribers, mostly autonomous

Adjacent Systems

  • Talking Head Script Studio — generates camera-to-face scripts across 6 content pillars. Session packs with energy levels. Separate from Content Studio but shares the braindump pipeline.
  • Video Studio — AI video generation via Higgsfield + Remotion. Content Studio motion exports land here automatically.
  • Instagram Channel — publishing, metrics, strategy reports, reply handling. Consumes Content Studio renders.

Post Compositions

The Composition Model

Every post in Content Studio is built from three layers: a template (defines copy slots and HTML structure), a palette (colours), and a layout (spatial arrangement). Templates come in two flavours: static (rendered to PNG via Puppeteer) and motion (rendered to video via Remotion).

TypeScript — TemplateDef (Static)
interface TemplateDef {
  id: string;                     // e.g. "announcement-bold"
  name: string;                   // Human label
  contentType: ContentType;        // Which content category
  copySlots: string[];             // e.g. ["headline", "detail", "tagline"]
  renderHtml: (
    copy: Record<string, string>,
    ratio: AspectRatio,
    options?: RenderOptions,
  ) => string;                    // Returns full HTML document
}

How Static Rendering Works

Each static template has a renderHtml() method that produces a complete HTML document with inline CSS. The template injects the copy, palette colours, layout metrics, and font faces into the HTML. Puppeteer launches headless Chrome, sets the viewport to the exact pixel dimensions of the chosen aspect ratio at 2× device scale, loads the HTML, screenshots it as PNG, and returns the buffer.

Render Flow
template.renderHtml(copy, ratio, options)  // → HTML string
  ↓
puppeteer.launch() → page.setViewport({ width, height, deviceScaleFactor: 2 })
  ↓
page.setContent(html) → page.screenshot({ type: "png" })
  ↓
uploadToCloudinary(buffer) → content_studio_renders row

Carousel Support

When slide_count > 1, the post is a carousel. The LLM generates an array of copy objects — one per slide — with instructions to build a narrative arc: “Slide 1 hooks, middle slides develop, final slide lands.” Each slide is rendered independently across all selected aspect ratios, producing slideCount × ratioCount total images.

Copy Correction

After initial generation, Andy can type a correction (“too corporate, pull it back”) which feeds the current copy + correction text back to the LLM. The correction history is stored as a JSON array on the post, preserving every edit request and timestamp. Corrections can target a specific slide in a carousel.

Layout System

Layouts control how text is arranged on the canvas — alignment, vertical position, type scale, spacing, content width. Every static template and every layout-supported motion template reads a MotionLayoutConfig object that drives computed pixel values via the computeLayout() function.

TypeScript — MotionLayoutConfig
interface MotionLayoutConfig {
  id: string;
  name: string;
  description: string;
  textAlign: "left" | "center" | "right";
  verticalPosition: number;     // 0–100 (top to bottom)
  headlineScale: number;        // multiplier on base font size
  detailScale: number;          // multiplier on detail font size
  lineHeight: number;           // headline line-height
  letterSpacing: number;        // px letter-spacing
  paddingScale: number;         // multiplier on base padding
  contentWidth: number;         // percentage of canvas width
  elementGap: number;           // px gap between elements
  isPreset: boolean;
}

Aspect-Ratio-Aware Scaling

The computeLayout() function takes canvas width and height, computes a base scale factor from canvasWidth / 1080, then applies an aspect-ratio adjustment: taller canvases (aspect < 0.8) scale up 8%, wider canvases (aspect > 1.3) scale down 8%. All font sizes, paddings, and gaps are computed from this scale factor multiplied by the layout’s individual scale parameters.

Scale Computation
function getCanvasScale(canvasWidth: number, canvasHeight: number): number {
  const widthScale = canvasWidth / 1080;
  const aspect = canvasWidth / canvasHeight;
  const aspectAdjust = aspect < 0.8 ? 1.08 : aspect > 1.3 ? 0.92 : 1.0;
  return widthScale * aspectAdjust;
}

Paired templates inherit their copy from the static version; motion-only templates define their own slots.

Animation Parameters

Each motion template declares its own tuneable parameters. Three types exist:

  • timing — numeric frame values (e.g. headline delay in frames)
  • easing — easing function names
  • toggle — boolean on/off (e.g. gradient pulse enabled)

Default values come from the template definition. User adjustments are stored as JSON on the post’s animation_params_json column.

Duration Control

All motion renders at 30fps. Each template defines defaultDuration, minDuration, and maxDuration in frames. Typical range: 2–6 seconds (60–180 frames). Duration is stored on the post as motion_duration_frames and overrides the template default when set.

SFX Timeline

Sound effects can be placed at specific frames on the motion timeline. Four built-in sounds ship with the system:

tick whoosh impact riser

Custom SFX can be uploaded to the sfx_library table. Each cue is a SfxCueData object: { sfxId, url, startFrame, volume }. Cues are stored in the animation params under an _sfxCues key.

Remotion Video Generation

Motion posts are rendered to video using Remotion — a React-based programmatic video framework. Each motion template is a React component registered as a Remotion <Composition> in remotion/index.ts.

Render Pipeline

1. Bundle          @remotion/bundler.bundle() → webpack bundle of all compositions
                     (cached — built once, reused across renders)

2. Select          selectComposition({ serveUrl, id: templateId, inputProps })
                     → resolves the composition React component

3. Render          renderMedia({
                       composition,  // with overridden width/height/duration
                       codec: "h264" | "vp8",
                       outputLocation: "/tmp/motion-{id}-{ts}.{fmt}",
                       inputProps     // copy, palette, params, sfx, layout
                     })

4. Upload          uploadToCloudinary(filePath, "superbad/content-studio/{postId}/motion")

5. Record          Insert content_studio_renders row (render_type: "motion")
                     Insert video_jobs row (engine: "remotion", status: "ready")

Promote Static to Motion

Any static post can be “promoted” to a motion post. The promoteToMotionAction creates a new post record with motion_enabled = 1, copies the copy from the selected slide, maps it to the motion template’s copy slots, and links back to the source via promoted_from_post_id. The original static post is preserved.

Section 07

Content Engine Pipeline

The Content Engine is a 6-stage autonomous pipeline that runs for SuperBad and for SaaS subscribers. It is the first product on the SaaS billing infrastructure. The differentiator: every piece of output reads the owner’s Brand DNA profile as perpetual context, producing voice-matched content rather than generic AI text.

Stage 1 — Research

Weekly scheduled_tasks job per owner. SerpAPI keyword research from seed keywords (auto-derived from Brand DNA + vertical + location). Each candidate keyword is:

  1. Rankability-scored against a static high-authority domain list (~500 entries in /data/high-authority-domains.json) plus live SERP data
  2. Content-gap-analysed: fetch + cheerio on top 3 ranking pages, Haiku identifies underserved angles
  3. Ranked. Top candidates enter the topic queue

Stage 2 — Topic Queue

Each topic gets a Haiku-generated outline (sections, key points, target word count, featured snippet flags). The queue is subscriber-visible but engine-managed — subscribers can veto topics but not reorder or add. Lifecycle: queued → generating → generated (or vetoed / skipped).

Stage 3 — Generation

Opus two-pass: the outline (from Stage 2) feeds into a full blog post generation call. The system prompt includes the owner’s complete Brand DNA profile (prose portrait, first impression, signal tags). The user prompt includes keyword, outline, content gaps, and competitor titles.

Drift Check

Every generated post passes a brand-voice drift check before entering the review queue. If the draft fails the drift threshold, it’s automatically regenerated once. A second failure surfaces a “voice drift flagged” warning but still enters review.

One Draft Maximum

The engine enforces a hard rule: only one unreviewed draft per owner at any time. It will not generate a new draft until the current one is approved or rejected. This prevents unreviewed content from piling up.

Stage 4 — Review

Split-pane surface: rendered preview left (~60%), rejection chat right (~40%). Approve triggers automatic fan-out. Reject triggers a feedback chat where the subscriber types corrections (“too corporate, pull it back”) and the LLM regenerates with the feedback as added context. Chat history persists.

Stage 5 — Publish

Blog publishes immediately on approval at [subscriber-domain]/blog/[slug]. Full SEO package: title tag, meta description, OG image, JSON-LD Article schema, canonical URL, table of contents, internal links, inline newsletter opt-in CTA.

Stage 6 — Fan-out

Approved post ──→ Newsletter rewrite  (Haiku: single standalone or editorial digest)
               ──→ Social drafts       (Haiku: one per platform — IG, LinkedIn, X, Facebook)
               ──→ Visual assets       (template render or AI image generation per draft)
               ──→ Outreach matching   (SuperBad only: match to prospect pool for content emails)

Subscriber Onboarding

Three wizard steps after Brand DNA completion:

  1. Domain verification — required, includes optional Google Search Console OAuth
  2. Seed keyword review — auto-derived from Brand DNA signals, subscriber approves/tweaks
  3. Newsletter preferences — send window day/time/timezone + optional list import

Engine starts research immediately after step 2.

Instagram Integration

Instagram is a full channel module at /lite/content/instagram. It covers publishing from Content Studio, metrics tracking, AI strategy recommendations, post boosting, and autonomous reply handling.

Publishing Flow

  1. User renders a Content Studio post (already uploaded to Cloudinary)
  2. “Post to Instagram” button opens the post modal
  3. Modal shows: account selector, image preview, aspect ratio picker (defaults 4:5), auto-drafted caption (LLM via instagram-draft-caption Sonnet job), drift score badge
  4. Server action creates media container(s) via Instagram Graph API, publishes, polls for FINISHED status
  5. Success creates an instagram_media row linked to the source Content Studio post via source_post_id

Metrics Dashboard

  • Account growth — follower count over time, reach, impressions, profile visits, website clicks
  • Content performance — per-post engagement score: (saves × 4 + shares × 3 + comments × 2 + likes × 1) / reach × 100
  • Audience insights — age/gender demographics, top cities, top countries, online hours

Two report types generated by LLM from metrics data:

Report TypeScheduleContent

Reply Handling

Inbound comments and DMs are classified by LLM (instagram-classify-inbound, Haiku) into: lead, complaint, collab, question, praise, spam, or simple. Draft replies are generated per type (Sonnet for comments and DMs). Replies flow through a review queue: pending_review → approved → sent. Lead-classified replies auto-create deals in the CRM. Voice corrections feed back into the reply model via instagram_voice_corrections.

Content Plans

Weekly content plans generated from strategy reports. Each plan contains typed slots (carousel, single, reel, story) with suggested dates, topics, and caption directions. Subscriber approves individual slots. One plan per account per week, enforced by a unique index.

Section 09

Newsletter System

How It Works

Newsletters are a fan-out product of the Content Engine. When a blog post is approved, the engine automatically rewrites it for email format using Haiku. The hybrid format rule:

  • Single post since last send → standalone newsletter rewrite
  • Multiple posts since last send → editorial digest with brief intro and per-post excerpts

One email per send window maximum. The rewrite includes a {{READ_MORE_LINK}} placeholder replaced at send time.

Send Window

Configurable per company: day of week, time, timezone. Default: Tuesday 10:00 AM AEST. The computeNextSendWindow() function handles DST-safe timezone conversion using Intl.DateTimeFormat.

The Copy System Prompt

Voice Rules

Dry, observational, self-deprecating. Never explain the joke. Short sentences. Leave room for the mutter. Ban “synergy”, “leverage”, “solutions”, “elevate”, “game-changer”. Real first. Headlines punchy and typographic. Taglines quieter, italic, one line. Return ONLY valid JSON.

Brand DNA as Perpetual Context

Every content generation call reads the owner’s Brand DNA profile. The injection follows a tiered pattern:

  • Haiku calls (research, outlines, social drafts, newsletter rewrites) — signal tags only
  • Opus calls (blog generation, outreach emails) — full prose portrait + first impression + signal tags
  • Sonnet calls (Content Studio copy, Instagram captions) — brand voice rules as system prompt

Cost Logging

Every LLM call logs input/output token counts and estimated AUD cost to external_call_log via the Cost & Usage Observatory. Logging is fire-and-forget — never blocks the response or throws on insert failure. Actor attribution tracks whether the call was internal (SuperBad), external (client), shared, or prospect.

Section 12

Implementation Tips

  1. Start with the template system. The TemplateDef interface is the foundation. Get one template rendering to PNG via Puppeteer before touching anything else. The renderHtml() method is just string interpolation — no framework magic, just HTML with inline CSS.
  2. The layout system is just maths. computeLayout() takes a config and canvas dimensions, returns pixel values. Build a preview that updates in real-time as you tweak sliders. The 10 presets are just hardcoded MotionLayoutConfig objects.
  3. Puppeteer needs a real Chromium binary. The resolveExecutablePath() helper finds the local Chrome/Chromium install. On CI/production, install puppeteer (with bundled Chromium) instead of puppeteer-core. The 2× device scale factor is important — without it, renders look fuzzy on retina screens.
  4. Remotion bundles once. The webpack bundle is cached via a module-level promise. First render is slow (~5s for the bundle), subsequent renders are fast. If you change a composition component, you need to restart the server to invalidate the bundle cache.
  5. Motion and static share copy slots. Paired motion templates declare the same copySlots as their static counterpart. Copy generated for a static post works for its motion version. The promote-to-motion flow exploits this directly.
  6. The Content Engine pipeline is gated at every step. Kill switches (content_automations_enabled, content_newsletter_enabled) gate the pipeline. The one-draft-maximum rule prevents runaway generation. The drift check prevents off-voice content from reaching subscribers. Build these gates first, then the generation logic.
  7. Brand DNA is not optional for the Content Engine. Without a completed Brand DNA profile, the engine falls back to generic voice descriptors (“professional, clear, approachable”). The entire value proposition is voice-matched content. Build and test with real Brand DNA profiles from the start.
  8. Newsletter scheduling is timezone-aware. The computeNextSendWindow() function uses Intl.DateTimeFormat for DST-safe conversions. Don’t use naive UTC offsets — Melbourne switches between AEST and AEDT, and the send window needs to land at the right local time year-round.
  9. SerpAPI is the expensive call. Keyword research hits a paid API with per-query pricing. The weekly research cadence is intentional — don’t increase it without understanding the cost impact. Ranking snapshots are similarly paced.
  10. Instagram Graph API has aggressive rate limits. Respect the container creation → publish → poll cycle. Carousel posts require child containers created before the parent. The 30-second polling timeout on publish status is a practical ceiling before giving up and logging the failure.
  11. Font pairings need the actual font files. Eight font pairings are defined, each mapping to woff2 files in /public/fonts/. For Puppeteer (server) rendering, fonts are loaded via file:// URLs. For browser preview, via /fonts/. If fonts look wrong, check the path resolution in getFontFacesForServer() vs getFontFacesForBrowser().
  12. The model registry is the single source of truth for LLM costs. Changing a job from Opus to Haiku is a one-line edit in lib/ai/models.ts. No feature code changes required. This is how you control costs — move jobs between tiers based on quality requirements and budget.
Final Note

The Content Studio and Content Engine share a philosophy: the human provides direction, the machine does the labour, and Brand DNA is the bridge between generic and genuine. Every LLM call, every template render, every newsletter rewrite reads the same personality profile. That’s the product. Everything else is plumbing.
